# UUID-IDs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Alle Entitäten auf UUIDv7 umstellen, mit Fremdschlüsseln, initialer Migration, typisiertem User-Zugriff und optimistischem Erstellen von Bits und Dependencies.

**Architecture:** Das Backend legt neue Zeilen nur per `insert` unter einer client- oder servergewählten UUIDv7 an (409 bei Kollision). Entities bekommen `uuid`-Spalten plus `@ManyToOne`-Relationen für echte FKs; das Schema für Produktion entsteht aus einer generierten Migration. Das Frontend erzeugt IDs selbst, zeigt neue Bits/Pfeile sofort und lässt Folge-Requests über eine Pending-Registry auf das zugehörige POST warten.

**Tech Stack:** NestJS 12, TypeORM 1.1 (Postgres 15), class-validator, Vitest (Backend mit SWC); Vue 3 + Pinia, Vitest + jsdom.

**Spec:** `docs/superpowers/specs/2026-10-14-uuid-ids-design.md`

## Global Constraints

- Keine Commits durch den Agenten — der Nutzer committet selbst (CLAUDE.md). Commit-Schritte entfallen; stattdessen am Ende eine Commit-Empfehlung.
- Keine neuen npm-Abhängigkeiten.
- UUID-Version für neu erzeugte IDs: **7**. Client-IDs beim Erstellen: `@IsUUID('7')`. Referenzen: `@IsUUID()` / `ParseUUIDPipe` (jede Version).
- Neue Zeilen nie per `save()` anlegen, immer `insertWithId()`.
- userId kommt ausschließlich aus dem JWT (`@CurrentUserId()`), nie aus dem Body.
- Alle `/api/bit|packet|dependency`-Controller behalten `@UseGuards(JwtAuthGuard)` und `@Throttle({ default: { limit: 300, ttl: 60000 } })`.
- Kein `any` in neuem Code.
- Qualitäts-Checks aus dem Repo-Root: `npm run lint`, `npm run type-check`, `npm test`, `npm run format`.

## Review Focus

1. Ein frisch erstelltes Bit wird gezogen, bevor das POST zurück ist → das PUT wartet auf das POST, kein 404, kein Zurückspringen (Task 7).
2. Browser hat noch ein altes Cookie mit numerischem `sub` → 401 und Login, kein 500 (Task 4).
3. Client schickt beim Erstellen die ID eines fremden Bits → 409, fremde Zeile unverändert (Task 3).
4. Kaputte ID in URL oder Body (`/api/bit/abc`, `bitIds: [1]`) → 400, kein 500 (Task 2/4).
5. Erstellen schlägt fehl → optimistischer Eintrag verschwindet, wartende Folge-Requests schlagen ebenfalls fehl, Reload stellt Server-Stand her (Task 7).

    if (value.id != null && this.rows.some((r) => r.id === value.id)) {
      throw new QueryFailedError('INSERT', [], Object.assign(new Error('duplicate key'), { code: '23505' }))
    }
    const row = this.add(value)
    return { identifiers: [{ id: row.id }] }
  }
```

/**
 * RFC 9562 UUID version 7: a 48-bit Unix millisecond timestamp followed by random bits.
 * Later IDs sort after earlier ones, also as plain strings. Kept in sync with
 * backend/src/common/uuid.ts.
 */
export function uuidv7(now: number = Date.now()): string {
  const bytes = crypto.getRandomValues(new Uint8Array(16))
  let ts = now
  for (let i = 5; i >= 0; i--) {
    bytes[i] = ts % 256
    ts = Math.floor(ts / 256)
  }
  bytes[6] = (bytes[6]! & 0x0f) | 0x70 // version 7
  bytes[8] = (bytes[8]! & 0x3f) | 0x80 // variant 10xx
  const hex = Array.from(bytes, (b) => b.toString(16).padStart(2, '0')).join('')
  return `${hex.slice(0, 8)}-${hex.slice(8, 12)}-${hex.slice(12, 16)}-${hex.slice(16, 20)}-${hex.slice(20)}`
}

/** Creation order for UUIDv7 (plain code-unit comparison, no locale rules). */
export function compareIds(a: string, b: string): number {
  return a < b ? -1 : a > b ? 1 : 0
}
```

```ts
/**
 * Creates that the server has not confirmed yet. A request that uses such an id (moving a new bit,
 * linking it, putting it into a packet) must wait for the create, or the server answers 404.
 */
const pending = new Map<string, Promise<unknown>>()

export function trackCreate(id: string, request: Promise<unknown>): void {
  pending.set(id, request)
  const forget = () => {
    if (pending.get(id) === request) pending.delete(id)
  }
  request.then(forget, forget)
}

/** Resolves once every given id exists on the server; rejects if one of the creates failed. */
export async function whenCreated(...ids: (string | null | undefined)[]): Promise<void> {
  await Promise.all(ids.map((id) => (id ? pending.get(id) : undefined)))
}

export function resetPendingCreates(): void {
  pending.clear()
}
```

  /**
   * Optimistic: the bit is on the canvas before the server answers. The server copy only fills in
   * what the client could not know (createdAt) — fields changed locally meanwhile stay local.
   */
  async function createBit(payload: { title: string; x: number; y: number; status?: number; priority?: number; dueDate?: string; notes?: string; color?: string }): Promise<Bit> {
    const draft: Bit = {
      ...payload,
      id: uuidv7(),
      x: Math.round(payload.x),
      y: Math.round(payload.y),
      status: payload.status ?? 0,
      packetId: null,
      order: 0,
      createdAt: new Date().toISOString(),
    }
    bits.value.push({ ...draft })
    const { packetId: _p, order: _o, createdAt: _c, ...body } = draft
    const request = api.post<Bit>('/api/bit', body)
    trackCreate(draft.id, request)
    try {
      const res = await request
      const idx = bits.value.findIndex((b) => b.id === draft.id)
      if (idx === -1) return res.data
      const local = bits.value[idx]!
      const changed = Object.fromEntries(
        Object.entries(local).filter(([k, v]) => v !== draft[k as keyof Bit]),
      )
      bits.value[idx] = { ...res.data, ...changed }
      return bits.value[idx]!
    } catch (e) {
      bits.value = bits.value.filter((b) => b.id !== draft.id)
      throw e
    }
  }
